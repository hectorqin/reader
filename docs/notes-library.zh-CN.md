# 读书笔记管理

[文档中心](README.md) · [架构](architecture.md) · [API](api.md) · [界面规范](ui.md)

本页是读书笔记管理的设计。第 1 期（全库笔记页与导出）、第 2 期（标签、章节标题、书评）和 AI 回答存为批注已实现；第 3 期是方向，动手前要补全设计。

## 1. 定位与边界

Reader 是读书笔记的**源头和整理台**：笔记在这里产生，在这里跨书查找、筛选、回到原文，然后流向读者自己的笔记工具。

做：

- 高亮、批注、书签的跨书汇总、搜索、筛选、删除；
- 每条笔记回到原文；
- 导出为 Markdown 与 JSON。

不做：

- 自由建页、块编辑器、双链与图谱。那是另一个产品，而且富文本并发编辑撑不起现在的
  last-writer-wins 同步（见[架构 §5](architecture.md)）；
- 在笔记页里新建笔记或改写原文、批注。笔记从正文产生，文字的编辑仍在阅读器的「工具 → 笔记」里。
  笔记页只做整理：打标签、删除，而且走的是同一条写入路径（离线队列 → 同步）。

## 2. 笔记与书的生命周期

笔记是长期资产，书的记录不能在读者不知情时把它带走。

`notes.book_id` 是 `ON DELETE CASCADE`，而扫描器会清掉「没有可用文件、也不在任何人书架上」的书。
读者把书从书架拿掉、文件随后被移走，下一次扫描就会连笔记一起删除。

规则：**还有未删除笔记或书评的书不被扫描器清理。** 扫描器的清理条件多一条
`id NOT IN (SELECT book_id FROM notes WHERE deleted = 0)`。书的记录留着，笔记页照常显示书名与作者；
文件回来后笔记自动重新可跳转（书的身份与路径无关）。文件不在时点笔记，阅读器会说明无法打开这本书。

没有采用「在笔记上存一份书名快照」：那要改表，还要回答快照与手动元数据谁说了算。
保留书的记录不需要改 schema，书名仍然只有一个来源。

合并重复书时笔记随书迁移，这是已有行为（`BrowseService`），不变。

## 3. 第 1 期：全库笔记页与导出

### 3.1 服务端

新增 `NotesLibraryService`（`server/src/services/notes-library.ts`），只读 `notes` 表。
同步（`SyncService`）仍然是笔记唯一的写入路径。

| 接口 | 作用 |
| --- | --- |
| `GET /api/v1/notes/library` | 当前账号的笔记，服务端筛选、分页 |
| `GET /api/v1/notes/library/books` | 有笔记的书及各自条数，供筛选 |
| `GET /api/v1/notes/export` | 按同样的筛选导出全部命中 |

筛选参数三个接口共用：

- `q`：在原文与批注里做不区分大小写的子串匹配；
- `type`：`highlight` / `note` / `bookmark`，留空为全部；
- `bookId`：只看一本书；
- `tag`：只看带这个标签的笔记，整个标签精确匹配。

列表另有 `page`、`pageSize`（默认 50，上限 200），按 `updated_at` 倒序。
页码超界不报错，返回空列表和真实的 `total`，由客户端夹到最后一页（[界面规范 §3.5](ui.md)）。

书名、作者取自 `ShelfService.getMany`（含手动元数据）；不在书架上的书退回 `books` 表里的值。

导出：

- `format=markdown`：按书分组，书按最近笔记时间倒序，书内按时间正序。原文为引用块，批注为正文。
  **不含书签**——书签没有文字，在笔记工具里只是噪声。日期按 `tz`（分钟偏移，与时长统计同义）换算。
- `format=json`：`{ version: 1, exportedAt, books: [{ id, title, author, notes: [...] }] }`，
  含书签与 `locator`，可用于备份或以后导入。
- 响应是 `{ filename, mime, content, count }` 而不是文件流：Android 外壳的 WebView 不处理下载，
  客户端拿到文本后自己决定是存文件还是复制。

Markdown 在书内按章节分组（见 §4）。服务端不知道书的章节顺序，章节按读者第一次在其中做笔记的时间排；
记录章节标题之前的旧笔记没有章节，排在该书最前面。

### 3.2 客户端

- 页面 `features/notes/pages/NotesPage.tsx`，路由 `#/me/notes`，懒加载；入口在「我的 → 内容 → 读书笔记」。
- 搜索词、类型、书、页码都在 URL 里（`q`、`type`、`book`、`page`），从正文返回时回到同一视图。
- 每条笔记显示类型、高亮颜色、原文、批注、书名与时间。点原文打开阅读器并定位到该处。
- 删除走已有的离线队列（`offline.deleteNote` → `sync.flush`），成功后重新请求列表再提示。
- 导出面板：下载 Markdown、下载 JSON、复制 Markdown。导出遵循当前筛选。

### 3.3 回到原文

笔记页用路由状态 `{ openAt: locator }` 打开 `/book/:id`。阅读器照常恢复上次位置，然后跳到笔记处
（文本锚点 `rt1:` 或位置 `r1:`）。定位不唯一或原文已变化时不猜测，提示无法定位并停在上次位置。

跳到笔记处与在阅读器里点笔记一样会成为新的阅读位置；想回去时用「书籍信息 → 阅读记录」。

## 4. 第 2 期：标签与章节标题

`notes` 表多两列，都有默认值（加法式迁移）：

- `chapter_title`：做笔记时阅读器显示的章节标题。新笔记由阅读器写入，编辑时保留。
- `tags`：读者自己的标签。一列存全部标签，每个标签一行、首尾各有一个换行，
  所以「带某个标签」是 `instr(tags, '\n标签\n')`，不会匹配到只是包含它的另一个标签。
  没有另建 `note_tags` 表：标签跟着笔记这一条记录走，同步仍然是「一条记录、last-writer-wins」，
  不需要第二种记录和第二套墓碑。一个账号的笔记量足以在读取时统计标签词表。

同步协议里笔记多两个**可选**字段 `chapterTitle`、`tags`（至多 10 个，每个至多 32 字）：

- 旧客户端不发送这两个字段。服务端把缺失当作「保持原值」而不是「清空」，
  所以旧客户端改一条批注不会抹掉新客户端打的标签；显式的 `tags: []` 才是清空。
- 旧服务端忽略不认识的字段；新客户端连到旧服务端时标签不会保存，拉取后本机的标签会随之消失。
- 旧版本的服务端跑在新库上时不读写这两列，已有的值保持不变。

笔记页：每条笔记显示章节与标签；点标签按它筛选；「标签」按钮打开编辑面板，可移除、输入新标签、
从已用过的标签里选。`GET /api/v1/notes/library/tags` 返回账号的标签词表与条数。

## 5. 书评

整本书的、不绑定位置的文字。每个账号每本书一篇。

**不是笔记的一种。** `notes.type` 上有 `CHECK` 约束，SQLite 不能加法式地放宽它；旧版本的服务端还会因为
不认识的类型拒绝整批同步。所以书评是单独的表 `book_reviews(user_id, book_id, body, updated_at)`，主键是
`(user_id, book_id)`，没有行就是没有书评。

**不进同步，在线保存。** 书评是坐下来写的，不是在路上边翻页边写的；为它在每个客户端再做一种同步记录、
一套离线队列和墓碑，代价远大于收益。保存是一个 `PUT`，最后一次写入为准；保存空内容即删除，所以不需要墓碑。
离线时保存会失败并提示，不会假装成功。

- 扫描器不清理有书评的书（§2）；合并重复书时书评随书迁移，两份都有时保留较新的一份。
- 笔记页选中一本书时，列表上方显示这本书的书评，可以写、改、删。书籍下拉里标出哪些书有书评；
  只有书评、没有笔记的书也会列出。
- 导出：书评放在所在书的开头。按书筛选或不筛选时，只有书评的书也会导出；按关键词、类型、标签筛选
  时，只导出命中笔记所在书的书评。JSON 里是每本书的 `review` 字段。

## 6. AI 回答存为批注

选区上的「问AI」（翻译、解释、提问）得到回答后，可以「存为批注」：在这段文字上新建一条批注，
批注内容是「AI 翻译 / AI 解释 / 问：……」加上回答，超出批注编辑器上限（4000 字）的部分截断。
它就是一条普通批注，走同一条离线队列与同步，所以会出现在读书笔记里、可以打标签、会被导出。
不保存的回答不留任何记录（服务端只按请求缓存回答本身）。
