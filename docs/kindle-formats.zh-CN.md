# Kindle 格式（MOBI / AZW3）

[文档中心](README.md) · [架构](architecture.md) · [使用手册](user-guide.zh-CN.md)

本页说明 Reader 如何阅读 Kindle 电子书：`.mobi`、`.azw3`、`.azw`。只支持**没有 DRM** 的文件。

## 1. 思路：服务端读，客户端当 EPUB 看

客户端从不接触 Kindle 容器。服务端读取文件，把它发布成和 EPUB 完全同形的东西：

| Kindle 里的东西 | 发布成 |
| --- | --- |
| 一个章节 | HTML 文档，虚拟路径 `text/part0003.xhtml`，清单里的 `href` 是 `xhtml:text/part0003.xhtml` |
| 图片、字体（资源记录） | `res/<序号>`，序号从 0 开始 |
| KF8 的样式表、SVG（flow） | `flow/<序号>.css` / `.svg` |
| 书内链接 | 带资源标记的 asset URL，`ref` 指向目标章节加锚点，和 EPUB 的章节链接相同 |

所以阅读器的分页、书内链接、脚注、目录、批注、书内搜索、按窗口加载长书都不需要为 Kindle 写新代码。
章节以 `text/html` 发布：MOBI 6 的正文是不合 XML 规范的旧式 HTML，按 XML 解析会失败。

没有采用的方案：

- **扫描时转成 EPUB 存进 DATA_DIR**：多一份需要失效、清理、备份的派生文件，而读取本身只要十几毫秒。
- **客户端解析**：Android 外壳和浏览器都要带一份解析器，离线缓存还得按整个文件存。
- **第三方 npm 包**：评估过的现成实现会把图片写到磁盘目录、在 HTML 里留下服务器的绝对路径，
  并且引入额外依赖。容器格式本身不大，自己实现约 700 行，没有新依赖。

## 2. 容器

`.mobi`/`.azw3` 是 Palm 数据库：一串记录。记录 0 是头部（PalmDOC 头、MOBI 头、EXTH 元数据），
之后是压缩的正文记录，再之后是图片、字体，以及描述正文结构的索引（INDX/TAGX/CNCX）。

两代格式共用这个容器（`server/src/indexer/formats/mobi-reader.ts` 只负责读容器）：

- **MOBI 6**（旧 `.mobi`、`.azw`）：一整段 HTML，章节之间用 `<mbp:pagebreak/>` 分隔，图片用 `recindex`，
  链接用字节偏移 `filepos`。
- **KF8**（`.azw3`，以及「混合 `.mobi`」的后半部分）：真正的 XHTML，拆成骨架（skeleton）和片段（fragment），
  样式表是独立的 flow，所有引用都是 `kindle:` URI。

混合 `.mobi` 同时带一份给旧设备的 MOBI 6 和一份 KF8，EXTH 121 给出 KF8 部分的起始记录。读 KF8 部分：
它有真正的样式表和字体。图片序号总是从第一个头部的资源起点算。

支持的压缩：无压缩、PalmDOC、HUFF/CDIC。正文解压后超过 256 MB 的拒绝。

## 3. 转换细节

**MOBI 6**

- 在每个 `filepos` 目标处插入 `<a id="filepos-N">`（一次拼接，不随链接数增长），再按分页符切章。
  落在标签内部的偏移退到标签开头。没有可读内容的切片（连续分页符）并入下一章，不产生空白页。
- `<img recindex>` 改成资源 URL；`<a filepos>` 改成章节链接，同章内的是裸锚点。
- 段落上的 `height`（段前距）和 `width`（首行缩进，负值为悬挂缩进）转成 CSS，否则浏览器会丢掉所有缩进。
  `<font>`、`align` 浏览器本来就认，保留。

**KF8**

- 按片段表把每个片段插回骨架，得到完整 XHTML。
- `kindle:embed` → 资源，`kindle:flow` → 样式表，`kindle:pos:fid:…:off:…` → 目标片段在该偏移处的第一个可落脚元素。
  元素自己的 `id` 优先；只有 `aid` 的元素补一个 `id="aid-…"` 供链接落脚。
- 样式表里的 `kindle:embed`（字体、背景图）同样改写；URL 里用裸 `&`，因为样式表不解码实体。

**目录**：有 NCX 用 NCX（可多级），否则每章取第一个标题，再否则「第 N 节」。

**元数据**：EXTH 的书名（503，缺失时用头部全名）、作者（100，多位用逗号连接）、出版社、简介、ISBN、主题、
日期、语言；封面取 EXTH 201，缺失时取 202 缩略图。身份标识用 ASIN，没有则用 ISBN。

## 4. 无法读取的文件

带 DRM、损坏、或根本不是 Kindle 格式的文件**仍然入库**，以文件名作书名、没有封面。打开时阅读器显示原因
（`422 BOOK_DRM` 或 `422 BOOK_UNREADABLE`），而不是让文件在书库里无声消失。Reader 不做任何 DRM 移除。

## 5. 性能

打开一本书要把正文全部解压，这是主要开销（实测几百 KB 到 3 MB 的书约 10 毫秒）。服务端按路径、大小和修改时间
缓存最近打开的 4 本书，翻页不会每章解压一次。章节 HTML 在第一次请求时生成并缓存在同一对象里。

## 6. 限制

- **不支持离线整书下载。** 「离线缓存」会提示此格式暂不支持；读过的章节文字仍按章缓存在本机。
  要做的话需要把章节和它引用的图片一起缓存，留作后续。
- **KFX**（`.kfx`、新版 Kindle 的私有格式）不支持。
- **OPDS**：外部目录同时提供 EPUB 和 Kindle 时默认下载 EPUB；只有 Kindle 时才下载 Kindle 文件。
- 测试用的 Kindle 文件由测试自己生成（`server/test/helpers/kindle-fixture.ts`）。**HUFF/CDIC 解压尚未验证**：
  没有生成器，手头的真实样书也都是 PalmDOC 压缩。遇到这类书读不出来时，请附上文件反馈。
