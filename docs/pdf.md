# PDF 在线与离线阅读

PDF 有两种解析模式：

| 模式 | 阅读方式 | 适合 |
| --- | --- | --- |
| **PDF.js（原版页面）** | 每页由 PDF.js 画在 Canvas 上，叠一层可选择的文本层；书签就是目录，书内搜索逐页查文本层 | 讲究版式的书：插图、表格、公式、扫描版 |
| **增强解析（提取正文重排）** | 服务端读出文字层，按书签切成章节，像 EPUB 一样阅读：可调字号与主题、朗读、高亮批注、书内搜索、按章离线；插图、表格、公式从原页面截取显示，代码排成代码块 | 以文字为主的书、论文、技术文档 |

管理员在「我的 → 服务配置 → 书库 → PDF 默认解析模式」设全站默认（默认是原版页面）；读者在阅读器「设置 → 阅读 → PDF 解析」为单本书另选，选择保存在服务器上，换设备仍然有效，并优先于全站默认。切换后重新打开这本书，停在同一页附近。

## 原版页面（PDF.js）

PDF 使用 PDF.js 在 Web Worker 中解析，当前页由 Canvas 和可选择的文本层显示。
每页对应阅读器的一个固定布局 section（`pdf`、`pdf:2` …），翻页、页码和阅读位置沿用现有机制。

- **目录**：有书签时用书签（保留层级），没有时列出每一页。
- **书内搜索**：服务端对原版页面返回 `SEARCH_LOCAL_PDF`，阅读器逐页读取文本层查找（未读到的页会按需读取它的字节区间），点结果跳到那一页。
- 选字高亮、批注和朗读尚未支持原版页面（见「后续」）。

### 在线打开

1. 优先检查当前服务器、账户下已下载的完整文件缓存。
2. 没有完整缓存时，仅通过 `HEAD /api/v1/books/:id/content` 获取长度与 Range 能力。
3. PDF.js 通过自定义 `PDFDataRangeTransport` 按需读取字节区间，块大小为 64 KiB；禁用流式全量下载和自动预取。
4. 每个 Range 请求走现有客户端 Transport，携带 Authorization，并沿用令牌续期、401 重试、账户切换检查与取消机制。令牌不会写入 PDF URL。
5. 服务端直接从请求的文件偏移读取，不再读取并丢弃区间前面的字节。

64 KiB 是分块粒度，不是首屏流量上限；实际读取量由 PDF 的索引、字体、图片和页面内容布局决定，部分文档仍可能需要读取大量数据。
代理必须保留 `HEAD`、`Range`、`Content-Length`、`Accept-Ranges` 和 `Content-Range`；不支持 Range 时显示错误，不隐式回退到完整下载。

## 增强解析

PDF 没有段落，只有摆在页面上的字形。服务端用 PDF.js 读出每页的文字片段及其位置（`server/src/indexer/formats/pdf-text-worker.ts`），再整理成读者期待的结构（`pdf-text.ts`，纯函数，规则都有单元测试）：

1. **行**：基线变化或文本层标明换行处断行；一行的字号取其中大多数字符的字号，行内的代码字体、脚注号不会把它变成标题。
2. **去掉页面装饰**：页眉页脚（同一行文字除数字外在三成以上页面的顶部或底部出现）、单独的页码、复述章节名的页眉（顶部一行里含书签标题），以及正文块左侧窄窄的页边批注。左侧的行若和正文一样宽，视为双栏的另一栏，保留。
3. **段落**：正文块的左边界取多数行的起点。新段落的依据是首行缩进、上一行提前结束、字号变化、段间空白或标题；跨页时上一页最后一行写满且下一页首行不缩进，就是同一段。中日韩文字之间直接相连，拉丁文字加空格，行尾连字符断开的单词接回。
4. **章节**：按书签切章。顶层只有一个书签（整本书的标题）时用下一层。书签记录的高度常略低于它指向的标题，所以优先落在本页上与书签同名的那一行，并把它排成标题（很多书的标题是加粗的正文字号，文字层看不出来）；更深的书签成为章内锚点，进入目录。没有书签时每 20 页为一章。
5. **插图、表格、公式**：见下一节。
6. **代码**：主要用等宽字体排的连续行是代码块（`<pre>`），按行保留缩进。按「一段」判断而不是逐行：代码清单的行号、单独的右括号常用正文字体，而正文里提到一个文件名也会用等宽字体。等宽字体按字体名识别（Courier、Mono、Cursor、CMTT 等）；PDF.js 把中日韩字体都标成等宽，所以它的等宽标记只用于非中日韩字体。代码底下的灰色底框属于代码块，不当作插图。
7. **页码标记**：每页开始处有 `<span class="pdf-page" id="pdf-page-N">`，章节项带起始页 `page`，供两种模式切换时定位到同一页。

### 插图、表格、公式

服务端画不了页面（那需要原生画布），所以只说出**位置**：章节里放一个占位
`<figure class="pdf-region" data-kind data-page data-box>`，`data-box` 是页面坐标里的矩形；阅读器用自带的 PDF.js
把这一块页面画出来（`web/src/formats/pdf-regions.ts`）。画出来的就是原书的样子，矢量图、表格线、公式排版都不变。

识别依据是页面上**画了什么**（工作线程跟踪变换矩阵，记录图片、嵌入图形和描边/填充的路径）和**用什么字体**：

- **插图**：图片、嵌入图形和画出的形状，相邻的合并成一块；块里的标注文字随图走。挡在大半页文字后面的是页面底色，不算。
- **表格**：同宽的横线上下排列（三线表三条，带框表格更多）；两条横线之间出现「表 N」这样的表题，就是下一张表。表题留作正文。
- **无线表格**：连续三行以上、每行都有两处以上的大间隔，且各行内部的列起点对得齐，也当作表格截图。
- **公式**：主要用数学字体（CMMI、CMSY、CMEX、XITS Math 等）、且独占一行（缩进、居中或不满行）的行，连同它旁边的分数线、根号线；同一基线上用正文字体的 `lim`、`max` 也并进来。
- **行内公式**：句子里带上下标、分数线、上下伸出明显超过正文行高的数学字体片段，在句中截成一张小图（`<span class="pdf-math"><img class="pdf-inline">`），高度和基线偏移用 em 表示，随字号缩放；普通的单个下标仍是文字。

截图上叠一层透明文字（`.pdf-region-text`，按页面坐标定位、字号随图宽缩放），所以图里的字可以选择、复制、朗读，书内搜索也能搜到；替代文字写明「第 N 页的表格/插图/公式」。

代码判断还会排除中文为主的行：正文里接连提到宏名、文件名的句子不当作代码。

占位图的宽度以正文字号为单位（`em`），所以图里的字和正文一样随字号缩放，最宽不超过版心。宽高比由 `width`/`height` 属性预先占好，画好后不会让分页跳动。同一章重排时复用已画好的图。

PDF 第一次需要画图时才打开：已下载整本时用本机文件，否则和原版页面一样按需读取字节区间。增强解析的离线下载会连同整本 PDF 一起下载，离线也能画；没有文件又断网时，占位处显示一行说明。

文字少到不足以阅读的 PDF（扫描版：平均每页不到 4 个字，或有文字的页不到三成）不重排：清单回到原版页面，附带 `notice` 说明原因，阅读器显示出来。

章节以 `pdf/part0003.xhtml` 这样的虚拟路径发布（`text/html`），和 Kindle 书一样，所以链接、批注、搜索、按窗口加载都和 EPUB 相同；清单的 `revision` 是 `pdf-text:<键>`，两种模式、两次提取的缓存不会混用。

### 代价与缓存

- 提取在独立的工作线程里进行，一次只做一本，超过 5 分钟终止；同一本书的并发请求共用一次提取。
- 结果写入 `DATA_DIR/derived/pdf-text/`，键由文件路径、大小、修改时间和提取器版本组成：重启不重做，文件变了或提取规则升级（`PDF_TEXT_VERSION`）会重做。这个目录可以随时删除，下次打开时重新生成。
- 实测（ARM 服务器）：15 页英文论文约 2 秒，158 页中文手册约 3 秒；之后打开读缓存。
- 服务端只读文字、不画页面，所以不需要 PDF.js 可选的原生画布包；镜像构建时用 `npm prune --omit=optional` 去掉它，镜像里仍然没有原生代码。

### 局限

- 多栏按内容流顺序读。
- 只有两列、或列起点参差的无线表格仍按逐行文字排。
- 图上的透明文字层按 PDF 的字形位置摆放，选区形状与原书一致，但不支持在图上做高亮批注。
- 不带连字符断开的等宽单词会被加上空格；竖排、从右到左的文字未专门处理。

## 离线与资源管理

- **原版页面**：在线阅读不会自动缓存完整 PDF。需要离线时使用整书下载；之后从账户隔离的完整文件缓存打开。
- **增强解析**：按章节范围下载（和 TXT、Kindle 一样），并连同整本 PDF 下载，用来离线画插图、表格和公式；即使整本文件已下载，增强解析模式仍按章节阅读。

PDF.js worker、CMap、标准字体和 WASM 解码资源随构建打包，由现有 PWA 机制缓存，不依赖外部 CDN。
切换页面会取消旧的渲染，关闭阅读器会取消请求、释放画布并销毁文档 worker。尺寸变化自动重绘；支持完整页面和适合宽度两种模式。

## 后续

原版页面上的选字高亮、批注和朗读（anx-reader、koodo-reader 都有）需要把文本层的选区映射回页面坐标并持久化，留作下一期。

## 验证

在 `web` 目录执行 `npm run ui:review:pdf`。脚本使用真实 Chromium 和带大段未引用数据的 8 MiB PDF，禁止不带 Range 的 GET，检查首屏流量、空闲时不预取、鉴权、文本层、页面跳转、尺寸变化及资源释放。
流量统计只计算 PDF 数据，不含阅读器脚本、worker、字体等静态资源。该构造样本用于验证按需读取机制，不代表真实扫描书的性能基准；尚需在实际书籍和 Android 真机上验收。

增强解析的规则（含插图、表格、公式、代码的识别）在 `server/test/pdf-text.test.ts` 里用手工构造的页面测试，端到端在 `server/test/helpers/pdf-fixture.ts` 生成的真实 PDF 上测试；开发时另用清华学位论文模板的示例与手册（中文、带书签）和一篇 arXiv 论文（英文）人工核对过，这些样本不入库。
