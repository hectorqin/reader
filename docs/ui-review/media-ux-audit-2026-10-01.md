# Media UI/UX 验收与优化报告

日期：2026-10-01
范围：媒体库、书架/书库、阅读器、扫描任务、播放页；移动端 390×844，桌面端 1120×900 生产构建场景。

## 已落地优化

### 扫描任务的恢复路径

失败扫描记录此前只有“删除历史”图标，用户无法从当前上下文恢复任务。现在失败记录同时提供“重新扫描媒体库”入口；当同一媒体库仍有排队或进行中的任务时，重试按钮会禁用并显示等待语义，避免重复提交。

### 扫描任务与 AI 刷新解耦

普通扫描轮询不再依赖 AI 扫描接口或完整对象上下文才能完成状态更新。这样扫描列表可以稳定呈现“进行中 / 失败 / 完成”，减少局部刷新时的空白、误导性加载和状态跳变。

## 视觉与交互观察

### P0：阅读页顶部内容可能被工具栏遮挡

移动端夜间主题截图中，章节标题的第一行贴近顶部工具栏，出现被遮挡的视觉风险。阅读正文应从工具栏安全区之后开始，尤其是在滚动恢复、切换主题、收起/展开工具栏后保持一致。

建议：将正文起始安全区绑定到实际 topbar 高度和 safe-area，而不是固定的短间距；切换主题和恢复阅读位置后重新校正滚动锚点。验收条件：章节标题不被遮挡，滚动到章节顶部时首行完整可读。

### P1：扫描任务操作需要从图标识别升级为语义分组

当前列表右侧使用删除、取消、重试图标，桌面端可理解，手机端在长列表中识别成本较高。

建议：失败状态将“重新扫描”作为主操作，删除作为次要操作；在 430px 以下的断点使用“重试”文字按钮或图标+文字，并在任务错误说明下提供恢复动作。保留 44px 最小触控区域。

### P1：任务状态应形成清晰的视觉层级

进行中任务使用边框卡片，失败和完成任务以普通行展示，状态差异明确但恢复动作不够突出。

建议：为进行中、失败、完成建立稳定的状态色和状态图标映射，同时保证暗色主题下文字与边框达到可读对比度；不要只依赖颜色表达状态，配合状态文字和图标。

### P1：设置页分组密度可进一步收紧

阅读设置底部存在较大空白，分段控件与标签的左右关系清晰，但内容密度偏低。

建议：将相关设置按“阅读方式 / 翻页行为 / 动画”分组，并使用组标题和短说明消除空白；在手机端每组之间保持 16–24px 节奏，避免单个控件漂浮。

### P2：媒体库卡片信息可读性

书架三列卡片在 390px 宽度下可用，但书名和作者信息依赖截断；操作菜单位于封面右上角，视觉上容易被误认为封面内容。

建议：长按或点击卡片后再显示操作菜单，或增加更明确的“更多”辅助文字；保证书名至少显示两行，作者显示一行，类型徽章不覆盖封面主体。

### P2：文件管理页需要更强的当前位置反馈

文件管理页的面包屑、文件列表、分页结构完整，但在深色主题和长列表中，当前目录与分页信息的视觉权重接近。

建议：强化当前目录名称，弱化技术性文件大小；分页器增加“上一页 / 下一页”语义标签，并在移动端固定在列表底部安全区内。

### P2：主题系统整体一致，但媒体与阅读器应共享语义 token

截图显示媒体页和阅读页都具备浅色、深色、米黄等主题，但两套变量命名和对比策略不同，后续容易出现“媒体页已切换，播放层或弹层仍使用旧背景”的问题。

建议：统一 `surface / paper / text / muted / border / accent / selection` 语义 token，并让播放器、弹层、任务面板只消费语义变量；为每个主题建立文本、控件、禁用态和焦点态对比度验收表。

## 验收结果

- 生产构建：通过。
- 媒体全量单元/组件测试：114 个测试文件、995 项全部通过。
- OpenList 真实媒体链路：通过，包含创建、扫描、凭据脱敏、远程音频播放、Range 请求和凭据轮换。
- 移动端 UI Review：既有报告 32 项视觉/交互检查全部通过，覆盖主题、面板、书架、书库、搜索、分页、窄屏和图片溢出。
