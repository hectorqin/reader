# 最近两天关闭 Issue 的需求方向分析

分析日期：2026-09-23（北京时间）。对象：hectorqin/reader 的关闭 issue，以及当前本地工作区代码。

## 结论

建议以“可靠的个人书库阅读器”为主线：优先保证进度、阅读和数据不会出错，再补齐书内检索、批注、多级目录、缓存管理等日常能力。远程来源继续沿用插件架构，避免把旧版 Legado 的全部兼容性负担重新放回核心。

建议顺序：**发布与接入说明 → 阅读/进度可靠性与数据恢复 → 书内搜索、批注和目录 → 朗读与离线体验 → 书源质量与生态互通。**

下文优先级是根据影响范围、当前基础和产品定位给出的建议，不是维护者已承诺的排期。

### 发布口径与工作区能力存在差异

[维护者在 #719 的回复](https://github.com/hectorqin/reader/issues/719#issuecomment-5773422708)表示“新版本目前聚焦本地书库，暂时不考虑支持远程书源相关功能”；[在 #720 的回复](https://github.com/hectorqin/reader/issues/720#issuecomment-5790657565)表示“目前还在开发中，未发布镜像……不支持 legado 书源”。

本地工作区已包含 local、OPDS、通用进程插件、远程章节、换源和追更。这说明本地开发能力与对外口径需要同步，但不能据此推断公开镜像已经提供这些功能。通用插件能力也不等于原生支持 Legado JSON 书源。

## 2. 需求方向与当前差距

### A. 安装、迁移和来源接入：P0

**依据：** [#719](https://github.com/hectorqin/reader/issues/719)、[#720](https://github.com/hectorqin/reader/issues/720)、#714、#666、#588。

**用户目标：** 部署成功后知道如何读到第一本书，旧用户知道哪些数据和书源可以继续使用。

**当前基础：** 已有 Docker 入门文档、插件管理 UI、npm/.tgz 安装和来源实例管理。入门文档仍展示 `cnb.cool/hectorqin/reader:latest`，但上述回复称尚未发布镜像；本次未核验镜像仓库标签。

**建议需求：**

1. 明确稳定版、开发版、旧版的入口、镜像标签、能力范围和数据目录，发布前核验文档命令可用。
2. 首次使用提供本地目录、OPDS、插件三种接入路径，并显示是否配置成功。
3. Legado JSON/订阅链接导入时给出明确兼容性说明；若由独立插件支持，提供具体插件及安装步骤，不能只提示“添加书源”。
4. 旧版迁移先明确账号、书架、进度、书源的可迁移范围，再设计预检查和迁移摘要；不能把旧 `/storage` 直接当新 `/data`。

**验收：** 新用户按发布文档部署并读到一本书；旧用户能在导入前知道兼容范围；不兼容输入显示可操作的解释。

### B. 阅读与进度可靠性：P0

**依据：** #702、#698、#696、#692、#687、#663、#655、[#652](https://github.com/hectorqin/reader/issues/652)、#645、#624、#596、#585、#580、#539、#536、#529、#512、#482。

**用户目标：** 不跳章、不漏段，换设备或重新打开仍在刚才的位置。

**当前基础：** 已有分页/滚动、手势和定位器、跨窗口加载、离线 outbox、按账号同步、按设备保存显示设置。它们是完善和回归的基础，不应重做一套阅读器。

**建议需求：**

1. 将“打开位置正确、翻页连续、退出前保存”作为版本验收门槛，覆盖 iOS Safari、Android WebView 和桌面浏览器。
2. 明确滚动到章末、点击翻页、键盘和音量键的跨章行为；手势一次只触发一个动作。
3. 字号、主题、旋转屏幕、工具栏显隐后保留正文锚点，不能靠旧页码恢复位置。
4. 显示同步状态和失败重试入口；提供进度历史/恢复能力，处理多设备离线后回传旧位置的情况。

**验收：** 连续读过章节边界后退出重进，正文位置与书架进度一致；A/B 两设备交替阅读及断网重连不发生无提示回退；切换排版不丢当前段落。

### C. 数据保护与大书库：P0/P1

**依据：** [#674](https://github.com/hectorqin/reader/issues/674)、#657、#642、#637、#632、#638、[#484](https://github.com/hectorqin/reader/issues/484)、#463、#644、#704、#697、#707、#618、#614。

**当前基础：** SQLite、独立 DATA_DIR、直接扫描 BOOKS_DIR、稳定内容身份、元数据覆盖、分页和目录递归筛选已有实现。书架服务默认每页 50、最多 200；不能再把“新增分页”作为空白功能立项。现有备份文档要求停机后复制完整数据目录。

**建议需求：**

1. 提供备份/恢复的产品入口或可靠管理命令，包含账号、进度、笔记、插件配置及一致性校验；恢复前可预览。
2. 把“文件暂时离线”“索引失效”“账号书架隐藏”“数据损坏”区分显示，提供重扫或恢复路径。
3. 验证 1 万本及更大书库下首屏、查询、增量扫描和同步性能；前端也要避免一次性载入全部数据。
4. 增加存储用量、封面/章节/下载缓存分类、日志轮转部署示例与可预览清理。
5. 本地 TXT 追加更新应考虑版本关系和进度继承。当前内容哈希参与身份，文件内容变化可能成为新副本；“自动重扫”并不自动保证追更连续性。

**验收：** 升级、重启和移动文件不丢阅读记录；备份恢复后账号和进度可用；缓存清理不删原书；大书库结果按页展示。

### D. 书内搜索、批注与内容整理：P1

**依据：** [#692](https://github.com/hectorqin/reader/issues/692)、[#709](https://github.com/hectorqin/reader/issues/709)、#710、#498、#654、#659、#688、#594、#643、#584。

**当前差距：**

- 书架/书库的书名、作者搜索已存在；没有找到完整的书内全文搜索入口和命中段落定位流程。
- 笔记、高亮、书签的数据类型、API 和离线同步已存在；没有找到阅读 UI 中创建、编辑、列表和定位的完整操作链。因此应归为“补齐产品交互”，不宜直接写成已完成。
- Web EPUB nav 解析将条目设为 `depth: 0`，章节匹配去掉 fragment；NCX 使用正则提取嵌套结构。服务端也主要提取章节标题。真实多级目录和章内锚点需要专项补齐。
- 元数据编辑已持久化，但不代表正文纠错、标题替换或 TXT 目录规则已支持。

**建议需求：**

1. 书内全文检索：结果摘要、命中高亮、跳到具体段落，保留返回原阅读位置的入口。
2. 选区高亮 → 添加批注 → 笔记列表 → 点击回正文，复用现有同步与墓碑删除机制。
3. 正确保留 EPUB nav/NCX 层级和 fragment，支持折叠、多级定位；TXT 增加可复用的章节规则及预览。
4. 正文纠错和过滤规则先采用可撤销的覆盖层，保存于 DATA_DIR；刷新不丢，规则更新可回退。只有用户明确选择且书库可写时才考虑写回原文件。

**验收：** 同一章多个搜索命中定位不同段落；批注跨设备恢复；三级目录不丢节点；刷新后纠错仍在且可撤销。

### E. 朗读体验与配置诊断：P1

**依据：** #690、[#689](https://github.com/hectorqin/reader/issues/689)、#635、#623、#616、#613、#608、#590、#580、#482。

**当前基础：** 已有浏览器、Android 原生及 HTTP 三类引擎，语音选择、逐句高亮、自动续章、服务端代理及 TTS 缓存上限。

**建议需求：** 增加配置检测与试听；区分无语音、鉴权失败、上游超时和浏览器播放限制；验证 HTTPS/反代/iOS 下播放、后台返回和续章定位；失败可重试或切换引擎。

**验收：** 管理员可用一次试听确认配置；续章从章首开始；失败有具体原因，不返回空成功；停止后没有残留音频继续播放。

### F. 离线缓存与书源质量：P1/P2

**依据：** [#513](https://github.com/hectorqin/reader/issues/513)、#717、#718、#716、#573、#672、#706、#703、#650、#658、#647、#491、#697。

**当前基础：** 已读章节优先使用服务端缓存，来源失效前已缓存的内容有继续读取的基础；搜索可流式展示和取消；已有同一来源实例内的换源和个人凭据接口。凭据接口不等于支持任意网站的交互登录，通用插件不等于兼容全部 Legado JS。

**建议需求：**

1. P1：整书/章节范围预下载、暂停/继续/取消、离线可读状态、按用户/书籍的配额和清理。明确“服务端缓存”与“设备断网可读”两个层次。
2. P2：换源候选显示当前章字数、最新章节、响应时间和获取错误；先解决明显空章，再考虑相似度，避免把相似度当内容正确性的证明。
3. P2：插件能力兼容表、登录状态/过期提示与必要的人工验证流程；解析和网站适配留在插件侧。
4. EPUB 导出和 NAS 保存作为独立能力评估，需要版本、保存位置、失败重试及存储边界。它与 OPDS 浏览是不同需求。

**验收：** 预下载后断网可读指定范围；来源停用不损坏已有书架和缓存；任务可取消且配额可见；换源失败仍保留原内容和进度。

### G. 生态互通和客户端覆盖：P2

**依据：** [#679](https://github.com/hectorqin/reader/issues/679)、#673、#717、#700、#353、#519、#693、#588、#712、#523、#634。

**当前基础：** 已有 OPDS 客户端获取能力和 Web/Android；当前检查范围内没有找到 OPDS 服务端目录发布和 Legado WebDAV 同步路由。

**建议：**

- 连接 Calibre 等 OPDS 书库归为已有功能的易用性完善。
- “把 reader 书库供其他客户端使用”需要 OPDS 服务端能力，另行立项，不能与 OPDS 客户端混为一谈。
- WebDAV 文件备份、账号数据备份、第三方阅读进度互通是三种问题。若做 Legado 兼容，单独定义书籍身份与定位映射适配器。
- 先明确支持的浏览器版本和电纸书低动画方案；独立 iOS/Windows ARM 客户端按需求规模另评估。

### H. 可选增强：P3

**依据：** #694 AI 章节总结、#699 外部评论、#711 自定义标题、#454 背景透明化、#475 RSS。

AI 速读适合在书内定位、内容访问和插件边界稳定后评估，需包含章节来源定位、调用成本和用户配置。网页标题隐私选项成本可能较低，可穿插实现。外部评论和 RSS 会扩展产品范围，建议暂缓。

旧 Java 安装、JVM 内存参数、Jackson CVE 等（#453、#626、#486、#670、#695）不应直接转为当前 Node 服务端的对应修改；应保留其“易部署、受限资源运行、依赖维护”的目标。#339、#613 属于生态分享，不直接按缺陷计数。

## 4. 建议下一批需求拆分

| 顺序 | 交付切片 | 可评审成果 |
| --- | --- | --- |
| 1 | 新旧版与来源接入说明 | 已核验部署命令、发布能力表、首次接入流程 |
| 2 | 进度可靠性 | 跨设备/离线/重排场景验收、同步状态、进度恢复方案 |
| 3 | 数据恢复 | 一致性备份、恢复校验、升级与目录变化验证 |
| 4 | 书内检索和目录 | 段落命中定位、三级目录、fragment 保留 |
| 5 | 笔记操作闭环 | 选区批注、笔记列表、回跳和跨设备同步 |
| 6 | 离线及听书 | 下载任务、缓存管理、TTS 试听和异常提示 |
| 7 | 插件生态增强 | 登录能力声明、换源质量、兼容矩阵和互通方案 |

优先级不按关闭时间或关闭原因机械排序；这批数据混有多年旧版本反馈、使用问题和生态分享。建议在立项时对各切片补充新版本真实用户验证，而非直接复刻旧版功能集合。
